# 一键关闭 Windows 服务脚本实现方案

## 1. 需求理解

基于现有 `scripts/start_all_windows.ps1` 和部署包启动脚本，新增一个 PowerShell 停止脚本，用于关闭本项目启动的 `logicserver`、`matchserver`、`roomserver` 三个服务。脚本不能只发送停止请求：应在等待优雅退出后，对仍存活的目标进程执行强制终止，并检查项目服务使用的 TCP/UDP 端口已不再被占用。

默认覆盖项目配置中的端口：TCP 8080（logicserver gRPC）、TCP 8081（logicserver HTTP 网关）、TCP 8090（matchserver）、UDP 9001（roomserver KCP）。

## 2. 影响范围

预计新增：

- `scripts/stop_all_windows.ps1`：项目源码目录下的一键停止脚本

预计修改：

- `scripts/start_all_windows.ps1`：补充停止脚本提示（如果与现有输出保持一致且无需改动，则不修改）
- `scripts/deploy_windows.ps1`：在部署包中同时生成 `stop_windows.ps1`，使复制出的部署目录也能一键停止服务

不修改 Go 业务代码、协议文件、配置文件和 Linux 脚本。

## 3. 设计方案

### 3.1 停止目标识别

脚本从 `$PSScriptRoot` 定位项目根目录，默认识别 `bin\windows` 下的三个服务可执行文件，并兼容部署包 `bin` 目录下的同名可执行文件。优先按进程的完整可执行路径匹配，避免误杀其他目录中恰好同名的程序。

同时保留按服务进程名收集的能力，作为 Windows 进程路径信息不可读取时的有限兜底；兜底仍只允许匹配固定的三个服务名，不按“所有占用端口的进程”盲目终止，避免误杀 MongoDB、Redis 或其他应用。

### 3.2 关闭流程

对每个目标服务：

1. 收集当前存活的目标进程并去重
2. 首先调用 `Stop-Process` 请求正常退出
3. 等待可配置的短超时，轮询确认进程已退出
4. 对超时仍存活的目标进程调用 `Stop-Process -Force`
5. 再次等待并确认进程句柄已消失

脚本应允许同一服务存在多个实例，全部处理；不存在目标进程时输出明确的“未运行”，不视为错误。清理失败、权限不足或进程仍存活时返回非零退出码。

### 3.3 端口释放确认

停止进程后，使用 `Get-NetTCPConnection` 检查 TCP 8080、8081、8090，使用 `Get-NetUDPEndpoint` 检查 UDP 9001。脚本轮询至端口释放或达到端口检查超时。

检查时只把仍存在的占用作为失败，并输出协议、端口、PID 和进程名，帮助定位残留进程。端口没有占用时输出确认信息。端口检查不主动杀死未知 PID，防止“保证端口空闲”导致对系统其他服务的误杀。

### 3.4 参数与执行方式

提供以下参数：

- `-GracefulTimeoutSeconds`：优雅停止等待时间，默认 5 秒
- `-PortCheckTimeoutSeconds`：端口释放等待时间，默认 5 秒
- `-Force`：跳过优雅等待，直接强制终止项目目标进程（仍只匹配目标路径/固定名称）
- `-Quiet`：减少非错误输出，便于脚本或 CI 调用

脚本统一使用 `$ErrorActionPreference = "Stop"`，但对“目标不存在”和 Windows 查询接口暂时不可用等预期分支显式处理。脚本结束时依据进程和端口检查结果设置退出码。

部署脚本生成的 `stop_windows.ps1` 使用部署根目录自身的 `bin` 作为匹配范围，避免停止源码目录中另一套服务。

## 4. 兼容性影响

- 不改变已有服务启动方式、服务端信号处理和网络协议
- 不改变任何已有端口配置
- 新增脚本对现有用户无破坏性影响
- 源码目录和部署目录均可使用一键停止能力
- PowerShell 5.1 兼容，不依赖 PowerShell 7 专属语法

## 5. 健壮性与边界处理

- 处理服务尚未启动、服务已自行退出、同名多实例、PID 在等待期间复用等情况
- 记录每个进程的停止阶段和最终状态
- 强制终止前明确只针对已通过目标匹配的 PID
- 端口仍被其他程序占用时报告具体 PID，而不是误杀未知程序
- 参数必须为非负/正数，超时时间过短时仍执行至少一次状态检查
- 查询端口失败与端口确实空闲区分处理

## 6. 性能考虑

服务数量和端口数量固定且很少，采用短间隔轮询不会产生明显开销。进程对象只收集一次并按 PID 去重，端口查询仅在停止后的有限超时时间内执行，不增加服务运行期负担。

## 7. 验证方式

在 Windows PowerShell 中：

1. 使用 `start_all_windows.ps1` 启动服务
2. 执行 `powershell -ExecutionPolicy Bypass -File .\scripts\stop_all_windows.ps1`
3. 确认三个服务进程不存在
4. 确认 TCP 8080/8081/8090 与 UDP 9001 无监听端点
5. 模拟重复执行，确认第二次安全返回
6. 模拟服务无法优雅退出，确认超时后被强制终止
7. 在 `dist\windows\demo_server` 中执行生成的 `stop_windows.ps1`
8. 运行 PowerShell 语法解析检查，并检查 git diff

Linux 脚本和 Go 单元测试不受本次改动影响；当前环境为 Windows，但若缺少已编译服务或无法实际启动依赖服务，将如实说明未完成的运行验证。

## 8. 自我审查

- 仅按端口杀进程会误杀 Redis、MongoDB 或其他应用，因此改为按项目可执行文件路径识别，端口检查只报告未知占用
- 仅依赖优雅退出无法满足“完全关闭”，因此增加超时后的强制终止和二次确认
- 只新增源码目录脚本会让部署包缺少对应能力，因此同步让 `deploy_windows.ps1` 生成部署版停止脚本
- 仅检查进程而不检查端口无法保证内核端点已释放，因此增加 TCP/UDP 轮询确认
- 不把所有监听端口作为清理目标，避免超过本项目职责边界；如果未知程序占用端口，脚本会失败并给出 PID，交由用户确认

## 9. 修正后的最终方案

新增 PowerShell 一键停止脚本，按项目服务可执行文件安全定位全部实例，先优雅停止、超时后强制终止，并对 TCP 8080/8081/8090 和 UDP 9001 做最终释放确认；同时让 Windows 部署包生成对应的停止脚本。脚本不主动终止未知程序，只在未知 PID 占用端口时报告失败，从而兼顾“完全关闭项目服务”和避免误杀系统/外部服务。

等待用户确认后开始修改脚本并执行验证。
